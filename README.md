# Лабораторная работа 3 — кластеризация смартфонов

Исследование Mobile Price Classification: K-Means и Gaussian Mixture на семи аппаратных характеристиках. `price_range` изолирован от обучения. Исходное ТЗ сохранено в [docs/SPECIFICATION.md](docs/SPECIFICATION.md).

Результат — [Lab3_Clustering.ipynb](Lab3_Clustering.ipynb), содержащий выполненные ячейки, графики, таблицы и численные выводы на русском языке. Ноутбук самодостаточен: вспомогательные функции включены в его первую ячейку. Для просмотра и запуска откройте его в VS Code с расширением Jupyter и выберите Python из `.venv`.

## Установка и воспроизведение (PowerShell, Python 3.13)

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe build_notebook.py
.\.venv\Scripts\python.exe -m unittest -v
.\.venv\Scripts\python.exe verify_notebook.py
```

`requirements.txt` задаёт допустимые диапазоны версий, `requirements-lock.txt` фиксирует фактически проверенное окружение Windows/Python 3.13. Первоначальная загрузка общедоступных данных идёт через `kagglehub`; необходим интернет и доступность Kaggle. Токены и `.env` соседних проектов не используются. Последующие запуски используют кэш Kaggle.

Генератор выполняет ноутбук в чистом ядре, извлекает рассчитанные аналитические тексты и вставляет их в следующие Markdown-ячейки. `results.json` содержит эти же выводы для быстрой проверки. Если изменены параметры или данные, заново запустите генератор: обычный Run All пересчитывает код и графики, но статические Markdown-выводы не обновляет. При ошибке выполнения сохраняется `Lab3_Clustering.failed.ipynb` для диагностики.

Включены статистики распределений и Шапиро–Уилк, дисперсии/CV/корреляции, IQR/Z-аномалии и винзоризация, Hopkins с uniform-контролем, три масштабирования, pairplot, подбор k и силуэтные профили, дендрограмма, геометрические и внешние метрики, венгерское сопоставление, 66 конфигураций K-Means, четыре типа ковариаций GMM, сетка DBSCAN, PCA и физические портреты центров.

Ожидаемые в ТЗ величины H, силуэта и ARI проверяются расчётом. Они не подставляются как результаты. k=4 — предписанный сценарий, который явно отделён от оптимума внутренних метрик. Ценовые метки используются для внешнего аудита, графиков чувствительности ARI и предусмотренной ТЗ эталонной PCA-панели; по ним не выбираются признаки или параметры. Разделимость технических групп не гарантирует восстановления цен.

Команды и фактические результаты проверок: [docs/VALIDATION.md](docs/VALIDATION.md).
